Lint Node.js code with the recommended `eslint-plugin-n` ruleset, guard against raw `console` and `process.exit`, and relax hashbang enforcement on source-level CLI entry points and scripts.

## Why Use This Preset?

1. Applies `eslint-plugin-n`'s recommended rules for Node.js correctness and unsupported APIs.
2. Bans raw `console` output so logging flows through the Logger toolkit battery instead.
3. Disallows `process.exit()` so error handling stays structured rather than terminating abruptly.
4. Warns on synchronous APIs so you avoid blocking the event loop.
5. Turns off hashbang enforcement for source-level <Terminology title="A tool you drive by typing commands in the terminal" to="/docs/quickstart/terminology#fundamentals" color={true}>CLI</Terminology> entry points, since the `bin` field points to the build output rather than the source file.
6. Lets files under `scripts/` carry a shebang or leave it out, so scripts you run directly from the shell lint cleanly without a per-repo exception.

## Usage

Import `runtimeNode` from the ESLint presets entry and spread it into your <Terminology title="One file with a flat list of configs, no cascading files" to="/docs/quickstart/terminology#builds-and-tooling" color={true}>flat config</Terminology> after the language layer, in the documented layer order.

```ts title="eslint.config.mts"
import {
  dxCodeStyle,
  dxIgnore,
  langTypescript,
  runtimeNode,
} from '@cbnventures/nova/presets/eslint';

export default [
  ...dxIgnore,
  ...dxCodeStyle,
  ...langTypescript,
  ...runtimeNode,
];
```

## What This Preset Configures

The preset registers `eslint-plugin-n` and applies its recommended Node.js ruleset, then adds project-specific rules and two scoped exceptions. Each group targets every script extension, except the hashbang exceptions, which apply only to <Terminology title="A tool you drive by typing commands in the terminal" to="/docs/quickstart/terminology#fundamentals" color={true}>CLI</Terminology> entry points and to JavaScript files under `scripts/`.

### Recommended rules

Registers `eslint-plugin-n` and spreads its recommended ruleset for Node.js. Nova disables `n/no-missing-import` because that rule can reject valid conditional package exports; TypeScript or `checkJs` remains the source of truth for module resolution.

### Bad habits

| Rule              | What it enforces                                                                   |
|-------------------|------------------------------------------------------------------------------------|
| `no-console`      | Bans raw `console` output so logging flows through the Logger battery.             |
| `no-process-exit` | Disallows `process.exit()` so error handling stays structured.                     |
| `no-sync`         | Warns on synchronous APIs like `fs.readFileSync` so the event loop is not blocked. |

### CLI hashbang

| Rule         | What it enforces                                                                                                                   |
|--------------|------------------------------------------------------------------------------------------------------------------------------------|
| `n/hashbang` | Disabled on `src/bin/index.*` and `src/cli/index.*`, since the `bin` field points to the build output rather than the source file. |

### Script hashbang

| Rule         | What it enforces                                                                                                                                                                                                                                    |
|--------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `n/hashbang` | Disabled on `scripts/**/*.js`, `scripts/**/*.cjs` and `scripts/**/*.mjs`, since a script run directly from the shell needs a shebang and a script run another way does not. The rule can only require or forbid one, so turning it off allows both. |
