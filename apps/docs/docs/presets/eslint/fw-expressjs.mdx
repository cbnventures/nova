Represent Express.js explicitly in a Nova ESLint composition. Express does not add language syntax, globals, or general-purpose lint rules beyond Node.js, so this framework layer is intentionally a named marker rather than an unfinished preset.

## Usage

Use it after the language layers and before `runtimeNode`.

```ts title="eslint.config.mts"
import {
  dxCodeStyle,
  dxIgnore,
  fwExpressjs,
  langTypescript,
  runtimeNode,
} from '@cbnventures/nova/presets/eslint';

export default [
  ...dxIgnore,
  ...dxCodeStyle,
  ...langTypescript,
  ...fwExpressjs,
  ...runtimeNode,
];
```

## Why Keep an Empty Framework Layer?

The named layer keeps generated projects structurally consistent and gives Nova one framework-specific extension point if Express ever requires safe shared configuration. Runtime behavior remains in `runtimeNode`, and application-specific middleware policy remains with the consumer.
