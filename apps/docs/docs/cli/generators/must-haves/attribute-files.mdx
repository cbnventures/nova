Regenerate every `.gitattributes` file declared under `attributeFiles` in `nova.config.json` from Nova bundles and project-owned patterns.

## Why Use This Command?

- Keeps the line-ending rules for files baked into Docker images in one place, so a Windows checkout never ships CRLF shell scripts.
- Separates reusable Nova defaults from project-specific patterns.
- Writes each file in full with the standard Nova header, so the file always matches its configuration.

## Requirements

- **Node.js runtime** — Use any Node.js <Terminology title="A release line that keeps getting fixes for a long time" to="/docs/quickstart/terminology#fundamentals" color={true}>LTS</Terminology> release.
- **Project root** — Run the command from the directory containing `nova.config.json` and the top-level `package.json`.

## Options

| Flag                 | Description                                                         |
|----------------------|---------------------------------------------------------------------|
| `-d, --dry-run`      | Validate and render every configured entry without writing files.   |
| `-r, --replace-file` | Overwrite existing files instead of creating `.nova-backup` copies. |

## Config Fields

Each `attributeFiles` key is an exact project-relative path beginning with `./` and ending in `.gitattributes`.

| Field      | Type       | Description                                                   |
|------------|------------|---------------------------------------------------------------|
| `bundles`  | `string[]` | Ordered Nova bundles whose lines open the file.               |
| `patterns` | `string[]` | Project-owned attribute lines written after the bundle lines. |

```json
{
  "attributeFiles": {
    "./packages/docker/.gitattributes": {
      "bundles": ["docker-scripts"],
      "patterns": ["*.conf text eol=lf"]
    }
  }
}
```

## Supported Bundles

| Bundle           | Lines                                                                           |
|------------------|---------------------------------------------------------------------------------|
| `docker-scripts` | `rootfs/** text eol=lf`, `project/** text eol=lf`, and `stages/** text eol=lf`. |

## How It Works

The command reads every configured entry and builds its lines in this order:

1. **Bundle lines** — Each bundle's lines, in the order the bundles are listed.
2. **Pattern lines** — Each project pattern, after every bundle line.
3. **Duplicates** — A line that already appeared is dropped. Lines that differ only in spacing count as the same line.

A pattern that names a path a bundle already sets, with different attributes, is an error. For example, `rootfs/** binary` next to the `docker-scripts` bundle stops the command. Remove the pattern, or drop the bundle and list every line as a pattern.

Nova renders every entry before it writes anything, so one bad entry leaves every file untouched. Each file is written in full and opens with the standard "generated by @cbnventures/nova" header that points back to this page.

The Docker scaffold registers `./packages/docker/.gitattributes` with the `docker-scripts` bundle instead of writing the file itself. Run this command after scaffolding to create it.
