Refresh the **introduction** in your `README.md` from <Terminology title="The one file that tells Nova how your repo is laid out" to="/docs/quickstart/terminology#nova-concepts" color={true}>`nova.config.json`</Terminology>.

## Summary

The `update-introduction` recipe rewrites the introduction of a `README.md` file so project or profile prose stays in sync with `nova.config.json`. It reuses the exact builder the `generate must-haves read-me` command uses, so the spliced introduction is byte-identical to a freshly generated region.

The recipe only touches the marked region. Everything before the `<!-- nova-region: introduction -->` marker and everything after the `<!-- nova-region-end: introduction -->` marker is left byte-identical, so hand-written prose around the introduction is never disturbed.

## Why Use This Command?

1. Keeps the README introduction aligned with the canonical long project description.
2. Rewrites only Nova's introduction region so surrounding prose remains untouched.
3. Makes messaging updates repeatable without regenerating the entire README.

## Requirements

- **An existing `README.md`** — The recipe updates a file in the project root; it does not create one. Use `generate must-haves read-me` to create the initial file.
- **The `introduction` region markers** — The `README.md` must contain the `<!-- nova-region: introduction -->` and `<!-- nova-region-end: introduction -->` markers. A `generate must-haves read-me` file has them by default.
- **Introduction text** — Project mode uses `project.description.long`. Profile mode uses the `readme.profile.introduction` paragraph array and joins its items with a blank line.

## Behavior

The recipe follows an in-place splice so it can only ever rewrite the region it owns.

- **Region gate** — The `introduction` region markers must both be present and correctly ordered. If the markers are absent, misordered, or the `README.md` was not generated by Nova, the recipe warns that the region markers were not found and returns without writing.
- **Region-only splice** — Only the content between the markers is replaced. The markers and all content outside them are preserved exactly.
- **Not applicable** — When the current `nova.config.json` yields no introduction, the recipe warns and returns without touching the file.
- **Profile prose** — Profile mode writes the configured introduction directly instead of adding the project-style **Introduction** heading.
- **Workspace copies** — Profile mode applies only to the root `README.md`. Consumer-workspace copies are refreshed with the project introduction from `project.description.long`, as if `readme.profile` were not set.
- **Idempotent** — When the regenerated introduction already matches the file on disk, the recipe reports that the introduction is already up to date and makes no write.

## Settings

Settings are configured in `nova.config.json` under the `recipes.read-me` key. The `update-introduction` recipe is controlled by a single `enabled` toggle:

```json
{
  "recipes": {
    "read-me": {
      "update-introduction": {
        "enabled": true
      }
    }
  }
}
```

When the recipe is not enabled, it warns and returns without touching any files.

## Options

| Flag                 | Description                                          |
|----------------------|------------------------------------------------------|
| `-d, --dry-run`      | Run without writing any files.                       |
| `-r, --replace-file` | Replace the original file without creating a backup. |
