Scaffold a **Next.js** workspace with React, TypeScript, and the App Router.

You can run this directly from an empty location; `scaffold starter base` is not a prerequisite. Nova creates the monorepo root and the first Next.js workspace together.

## Why Use This Command?

1. Installs Next.js 16 with React 19, TypeScript, and the App Router so you can start building pages immediately.
2. Auto-detects monorepo or workspace mode so the same command works whether you're starting fresh or adding to an existing project.
3. Provides `dev`, `prod`, `check`, `build`, and `clean` script groups whose top-level commands delegate to adjacent `name:*` steps through Nova's script runner.
4. Runs Next.js type generation before separate app, configuration, and Vitest type checks. Vite's test types never enter Next.js production compilation.
5. Enables Nova's complete custom ESLint rules and a starter Vitest suite while leaving every rule open to consumer overrides.
6. Optionally enables Next.js standalone output and adds a production Docker image without changing the platform-neutral default.

## Requirements

- **Node.js runtime** — Use any Node.js <Terminology title="long term support" to="/docs/quickstart/terminology#fundamentals" color={true}>LTS</Terminology> release.
- **Empty directory** (monorepo mode) or **<Terminology title="project root" to="/docs/quickstart/terminology#git-and-workflow" color={true}>monorepo root</Terminology>** (workspace mode) — The command auto-detects which mode to use.

## Options

| Flag                      | Description                                                                          |
|---------------------------|--------------------------------------------------------------------------------------|
| `-d, --dry-run`           | Run without writing any files.                                                       |
| `--name <name>`           | Project slug when creating a new monorepo; omit at an existing root.                 |
| `--non-interactive`       | Use flags and defaults without opening prompts.                                      |
| `--workspace-name <name>` | Workspace directory name.                                                            |
| `--output <dir>`          | Output directory.                                                                    |
| `--docker-image`          | Enable Next.js standalone output and add `.dockerignore`, `Dockerfile`, and Compose. |

## How It Works

### Interactive Wizard

When run without flags, the command walks you through an interactive wizard:

**Monorepo mode** (no `package.json` found):

1. **Project name** — Enter a slug for your monorepo (e.g. `my-app`).
2. **Workspace name** — Enter a slug for the workspace directory (default: `nextjs`).
3. **Where should the project be created?** — Choose between creating a new directory or building in the current working directory.
4. **Output directory** — If creating a new directory, confirm the path (default: `./{project-name}`).
5. **Run generators** — Optionally run project-level generators (`.editorconfig`, `.gitignore`, `LICENSE`, etc.).

**Workspace mode** (`package.json` with `workspaces` found):

1. **Workspace name** — Enter a slug for the workspace directory (default: `nextjs`).
2. **Output directory** — Confirm the workspace path (default: `./apps/{workspace-name}`).

Nova reads the project slug from the root `nova.config.json`; it does not ask you to rename the project or package.

### Non-Interactive Mode

Agents and automation should add `--non-interactive`. A new monorepo needs `--name`, `--workspace-name`, and `--output`. An existing monorepo needs only `--workspace-name` and `--output`; omit `--name` because Nova reads the root project slug.

## Naming, Registration, and Safety

For project slug `my-app` and workspace slug `web`, Nova names the package `my-app-app-web`. The same name is written to the workspace `package.json` and its `nova.config.json` entry. If the root `workspaces` globs do not include the selected output, Nova adds that exact relative path to the root `package.json`.

Before writing, Nova requires a readable root `package.json` and `nova.config.json`, keeps the output inside the monorepo, rejects duplicate paths and names, and lists any template files it would overwrite. `--dry-run` performs these checks without changing the project.
