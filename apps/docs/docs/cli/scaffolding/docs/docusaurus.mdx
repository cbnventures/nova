Scaffold a **Docusaurus** documentation workspace.

You can run this directly from an empty location; `scaffold starter base` is not a prerequisite. Nova creates the monorepo root and its documentation workspace together.

## Why Use This Command?

- Installs Docusaurus and asks which Nova visual preset to apply so the generated site starts with an intentional look and behavior.
- Auto-detects monorepo or workspace mode so the same command works whether you're starting fresh or adding to an existing project.
- Provides `dev`, `prod`, `check`, `build`, `clean`, and `i18n` script groups whose top-level commands delegate to adjacent `name:*` steps through Nova's script runner; the child steps run Docusaurus, TypeScript, Vitest, and the preset's i18n commands directly.
- Pins TypeScript `6.0.3` and composes Nova's essentials, strict, and Docusaurus TSConfig presets with the local `@site/*` alias.

## Requirements

- **Node.js runtime** — Use any Node.js <Terminology title="long term support" to="/docs/quickstart/terminology#fundamentals" color={true}>LTS</Terminology> release.
- **Empty directory** (monorepo mode) or **<Terminology title="project root" to="/docs/quickstart/terminology#git-and-workflow" color={true}>monorepo root</Terminology>** (workspace mode) — The command auto-detects which mode to use.

## Options

| Flag                      | Description                                                          |
|---------------------------|----------------------------------------------------------------------|
| `-d, --dry-run`           | Run without writing any files.                                       |
| `--name <name>`           | Project slug when creating a new monorepo; omit at an existing root. |
| `--non-interactive`       | Require every answer as a flag and do not open prompts.              |
| `--workspace-name <name>` | Workspace directory name.                                            |
| `--output <dir>`          | Output directory.                                                    |
| `--preset <name>`         | Nova visual preset written to `docusaurus.config.ts`.                |

## Config Fields

| Field                | Description                                                                                                                                                  |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `project.name.slug`  | Required in workspace mode and used to derive the package and registered workspace name. In monorepo mode, written from `--name` or the project-name answer. |
| `project.name.title` | Written in monorepo mode, title-cased from the project slug.                                                                                                 |

## How It Works

### Interactive Wizard

When run without flags, the command walks you through an interactive wizard:

**Monorepo mode** (no `package.json` found):

1. **Project name** — Enter a slug for your monorepo (e.g. `my-docs`).
2. **Workspace name** — Enter a slug for the workspace directory (default: `docusaurus`).
3. **Where should the project be created?** — Choose between creating a new directory or building in the current working directory.
4. **Output directory** — If creating a new directory, confirm the path (default: `./{project-name}`).
5. **Nova visual preset** — Select the visual identity written to `docusaurus.config.ts` (default: `foundry`).
6. **Run generators** — Optionally run project-level generators (`.editorconfig`, `.gitignore`, `LICENSE`, etc.).

**Workspace mode** (`package.json` with `workspaces` found):

1. **Workspace name** — Enter a slug for the workspace directory (default: `docusaurus`).
2. **Output directory** — Confirm the workspace path (default: `./apps/{workspace-name}`).
3. **Nova visual preset** — Select the visual identity written to `docusaurus.config.ts` (default: `foundry`).

Nova reads the project slug from the root `nova.config.json`; it does not ask you to rename the project or package.

### Visual Presets

| Value      | Visual direction                                        |
|------------|---------------------------------------------------------|
| `envoy`    | Purple and cyan with rounded, elevated surfaces.        |
| `foundry`  | Warm orange and amber with rounded, elevated surfaces.  |
| `lantern`  | Warm amber and indigo with tactile paper-like surfaces. |
| `marshal`  | Documentary green and red with compact, flat surfaces.  |
| `sentinel` | Teal and indigo with rounded, flat surfaces.            |
| `signal`   | Red and amber with sharp, compact surfaces.             |

### Non-Interactive Mode

Agents and automation should add `--non-interactive`. A new monorepo needs `--name`, `--workspace-name`, `--output`, and `--preset`. An existing monorepo needs `--workspace-name`, `--output`, and `--preset`; omit `--name` because Nova reads the root project slug.

## Naming, Registration, and Safety

For project slug `my-docs`, Nova names the package `my-docs-docs` and writes that same identity to `nova.config.json`. The package name does not change when you choose a different workspace directory. If the root `workspaces` globs do not include the selected output, Nova adds that exact relative path to the root `package.json`.

A Nova project has one canonical workspace with the `docs` role, so the command refuses to create a second one. Before writing, Nova also requires a readable root `package.json` and `nova.config.json`, keeps the output inside the monorepo, rejects duplicate paths and names, and lists any template files it would overwrite. `--dry-run` performs these checks without changing the project.
