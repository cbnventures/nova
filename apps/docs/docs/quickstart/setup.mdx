Nova supports three starting paths. Use the runner for a one-off, install into system, or install into project for presets and toolkits you can commit with.

## Requirements

- Node.js <Terminology title="long term support" to="/docs/quickstart/terminology#fundamentals" color={true}>LTS</Terminology>
- npm for the bootstrap commands shown on this page
- TypeScript `6.0.3` for projects that use Nova's TSConfig presets or compiler-backed utilities

Nova-managed projects may select npm, pnpm, or Yarn through an exact root `packageManager` descriptor. Corepack activates that pinned client when Nova-generated publish workflows run. See [Workspace Rules](/docs/quickstart/workspace-rules#root-package-manager) for the accepted values and why the field belongs only at the project root.

:::tip Quick Check
Run this command below to check the installed versions of your Node.js, package managers, operating system, installed browsers, and other dev tools directly:

```bash
npx --yes @cbnventures/nova@latest utility version
```
:::

## Choose Your Path

Choose **Run once (npx)** to try Nova or make a one-off change, **Install into system**, or **Install into project** to use preset configs and run commands any time.

:::info
If you wish, you can install Nova **globally** (into the system) and **locally** (into the project) at the same time. They will not conflict with each other.
:::

<Tabs groupId="setup-mode">
  <TabItem value="once" label="Run once (npx)" default>

    View the built-in help from the command below, or see **[CLI](/docs/cli/)**.

    ```bash
    npx --yes @cbnventures/nova@latest
    ```

  </TabItem>
  <TabItem value="global" label="Install into system">

    View the built-in help from the command below, or see **[CLI](/docs/cli/)**.

    ```bash
    npm i -g @cbnventures/nova@latest
    ```

    You can use the shorthand command for the **[CLI](/docs/cli/)** after installation:

    ```bash
    nova
    ```

  </TabItem>
  <TabItem value="local" label="Install into project">

    First, install Nova and the supported TypeScript compiler.

    ```bash
    npm i @cbnventures/nova@latest typescript@6.0.3
    ```

    Second, configure **TypeScript** through the `tsconfig.json` file. See **[TypeScript compatibility](/docs/presets/tsconfig/compatibility)** and **[TSConfig best practices](/docs/presets/tsconfig/best-practices)**.

    ```json
    {
      "extends": [
        "@cbnventures/nova/presets/tsconfig/dx-essentials.json",
        "@cbnventures/nova/presets/tsconfig/dx-strict.json"
      ]
    }
    ```

    Third, configure **ESLint** through the `eslint.config.ts` file. See **[ESLint best practices](/docs/presets/eslint/best-practices)**.

    ```ts
    import { dxCodeStyle, dxIgnore } from '@cbnventures/nova/presets/eslint';

    export default [
      ...dxIgnore,
      ...dxCodeStyle,
    ];
    ```

    Optionally, you can use the shorthand command for the **[CLI](/docs/cli/)**:

    ```bash
    nova
    ```

  </TabItem>
</Tabs>

## First Successful Check

After a project install, use this short path to create Nova's project metadata and prove the TypeScript and ESLint presets work together.

1. Start the guided config wizard from the project root.

   ```bash
   npx nova utility initialize
   ```

2. Keep the generated `nova.config.json` small at first. Project identity and the detected workspace entries are enough; the [complete config reference](/docs/quickstart/nova-config) is available when you need recipes, workflows, or environment delivery.

3. Add one repeatable check script to `package.json`.

   ```json title="package.json"
   {
     "scripts": {
       "check": "eslint . --max-warnings=0 && nova utility type-check"
     }
   }
   ```

4. Run the same check locally that continuous integration can run later. Use the client named by the root `packageManager` field.

   <Tabs groupId="package-manager-script">
     <TabItem value="npm" label="npm" default>

       ```bash
       npm run check
       ```

     </TabItem>
     <TabItem value="pnpm" label="pnpm">

       ```bash
       pnpm run check
       ```

     </TabItem>
     <TabItem value="yarn" label="Yarn">

       ```bash
       yarn run check
       ```

     </TabItem>
   </Tabs>

When that command passes, the minimal setup is complete. Add stricter presets and Nova generators one at a time so a failing check points to one understandable change.
