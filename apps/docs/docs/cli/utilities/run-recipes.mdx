Run every enabled <Terminology title="A script that tidies your files to match nova.config.json" to="/docs/quickstart/terminology#nova-concepts" color={true}>recipe</Terminology> in sequence.

## Summary

The `run-recipes` command traverses the complete recipe registry in sequence. Each recipe reads its own `nova.config.json` entry and performs work only when its individual `enabled` toggle is `true`. This is the single command that replaces chaining individual <Terminology title="A script that tidies your files to match nova.config.json" to="/docs/quickstart/terminology#nova-concepts" color={true}>recipe</Terminology> commands.

There is no category flag, so every invocation visits the `docker-hub`, `github`, `license`, `miscellaneous`, `nova-config`, `read-me`, and `package-json` categories. Disabled recipes perform no work.

Recipes reconcile settings or existing content and are safe to run again. They do not invoke <Terminology title="Writes a config file for you from a built-in template" to="/docs/quickstart/terminology#nova-concepts" color={true}>generators</Terminology>; generated files remain an explicit `nova generate ...` action.

## Recipe Categories

| Category        | Recipes                                                                                                                                                                          |
|-----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `docker-hub`    | `sync-identity`, `sync-policies`                                                                                                                                                 |
| `github`        | `sync-actions`, `sync-features`, `sync-identity`, `sync-labels`, `sync-policies`, `sync-rulesets`, `sync-security`                                                               |
| `license`       | `update-copyright`                                                                                                                                                               |
| `miscellaneous` | `fix-markdown-tables`, `remove-operating-system-files`                                                                                                                           |
| `nova-config`   | `normalize-order`                                                                                                                                                                |
| `read-me`       | `update-badges`, `update-credits`, `update-documentation`, `update-header`, `update-introduction`                                                                                |
| `package-json`  | `sync-identity`, `sync-ownership`, `normalize-modules`, `normalize-artifacts`, `sync-environment`, `normalize-dependencies`, `normalize-bundler`, `normalize-tooling`, `cleanup` |

## Why Use This Command?

- **One command to rule them all** — Instead of chaining `nova recipe package-json sync-identity && nova recipe package-json sync-ownership && ...`, run a single `nova utility run-recipes`.
- **Consistent ordering** — Recipes execute in their registered order, ensuring dependencies between recipes are respected.

## Requirements

- **Node.js runtime** — Use any Node.js <Terminology title="A release line that keeps getting fixes for a long time" to="/docs/quickstart/terminology#fundamentals" color={true}>LTS</Terminology> release with either the installed `nova` <Terminology title="A tool you drive by typing commands in the terminal" to="/docs/quickstart/terminology#fundamentals" color={true}>CLI</Terminology> or `npx`.
- <Terminology title="The one file that tells Nova how your repo is laid out" to="/docs/quickstart/terminology#nova-concepts" color={true}>`nova.config.json`</Terminology> — A valid <Terminology title="The one file that tells Nova how your repo is laid out" to="/docs/quickstart/terminology#nova-concepts" color={true}>`nova.config.json`</Terminology> file must exist at the project root with configured <Terminology title="One folder in the repo with its own package.json" to="/docs/quickstart/terminology#nova-concepts" color={true}>workspaces</Terminology>.

## Options

| Flag                 | Description                                                             |
|----------------------|-------------------------------------------------------------------------|
| `-d, --dry-run`      | Preview file, Docker Hub, and GitHub changes without sending mutations. |
| `-r, --replace-file` | Overwrite the original file instead of creating a `.nova-backup` copy.  |
