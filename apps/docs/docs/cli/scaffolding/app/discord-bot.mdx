Scaffold a **Discord bot** with discord.js, TypeScript, and explicit development and production entry points.

## Why Use This Command?

1. Separates Discord client construction from login so Vitest can exercise the starter without connecting to Discord.
2. Keeps the bot token in an untracked `.env` file while documenting the required key in the tracked `.env.sample`.
3. Uses a fixed-width Nova header and clear connection states while keeping the bot token out of terminal output.
4. Uses Nova's type-check and transpile utilities so checking and production output follow the same contract as other workspaces.
5. Can compose the background-service Docker profile with `--docker-image` without adding an HTTP port or health check.

## Requirements

- **Node.js runtime** — Use any Node.js <Terminology title="long term support" to="/docs/quickstart/terminology#fundamentals" color={true}>LTS</Terminology> release.
- **Discord application token** — Create a bot in the [Discord Developer Portal](https://discord.com/developers/applications), add it to a server with the `bot` scope, and provide its token as `DISCORD_TOKEN` after scaffolding.
- **Empty directory** or **<Terminology title="project root" to="/docs/quickstart/terminology#git-and-workflow" color={true}>monorepo root</Terminology>** — Nova auto-detects whether to create a project or add a workspace.

## Options

| Flag                      | Description                                                          |
|---------------------------|----------------------------------------------------------------------|
| `-d, --dry-run`           | Run without writing any files.                                       |
| `--docker-image`          | Add a production Node image and background-service Compose file.     |
| `--install`               | Install dependencies after scaffolding; this is the default.         |
| `--no-install`            | Skip dependency installation.                                        |
| `--name <name>`           | Project slug when creating a new monorepo; omit at an existing root. |
| `--non-interactive`       | Require every answer as a flag and do not open prompts.              |
| `--workspace-name <name>` | Workspace directory name.                                            |
| `--output <dir>`          | Output directory.                                                    |

## Output Files

| File              | Description                                                   |
|-------------------|---------------------------------------------------------------|
| `.env`            | Untracked Nova defaults and the blank `DISCORD_TOKEN` value.  |
| `.env.sample`     | Shareable Nova defaults and the required `DISCORD_TOKEN` key. |
| `src/bot.ts`      | Import-safe client factory, login flow, and status output.    |
| `src/bot.test.ts` | Offline Vitest coverage for intents, status, and validation.  |
| `src/index.ts`    | Runtime token lookup and bot startup.                         |
| `tsconfig.*.json` | Nova strict Node.js configs for source, tooling, and tests.   |
| `package.json`    | discord.js dependencies and Nova-managed workspace scripts.   |

## First Run

1. Create a Discord application and bot in the [Discord Developer Portal](https://discord.com/developers/applications).
2. Open the application's **Installation** page and add the bot to your server with the `bot` scope. Installing only the application-command integration does not add a visible bot member.
3. Set `DISCORD_TOKEN` in the generated `.env`, then run the workspace `dev` command shown by Nova.

Nova doesn't request or store the token during scaffolding, and the token should not be passed as a command-line flag.
The root `.gitignore` generated by every Nova scaffold excludes `.env` files while keeping `.env.sample` tracked.

When the token is missing, the generated bot prints these setup steps instead of a stack trace.

## Non-Interactive Mode

```bash
nova scaffold app discord-bot --non-interactive --name my-bot --workspace-name bot --output ./my-bot
nova scaffold app discord-bot --non-interactive --workspace-name bot --output ./apps/bot
nova scaffold app discord-bot --docker-image --non-interactive --name my-bot --workspace-name bot --output ./my-bot
```

## Registration

Nova registers the workspace with the `app` role and `trackable` policy. Its package name follows `{projectSlug}-app-{workspaceName}`.
