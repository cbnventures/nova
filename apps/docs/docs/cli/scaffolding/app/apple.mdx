Scaffold a universal **SwiftUI** application that shares one feature across iOS, macOS, tvOS, and visionOS, with a sample interface for each platform.

Nova stores the Xcode project as a readable `project.yml` definition, then generates the disposable `.xcodeproj` file with XcodeGen.
The generated `package.json` and `MARKETING_VERSION` share the strategy-aware initial version: `0.0.1` for SemVer or the current UTC `YYYY.M.0` period for CalVer. In an existing lock-step project, the app inherits the shared non-freezable version instead. Nova's changelog release flow keeps the two versions synchronized and advances the Apple build number from its initial value of `1`.

## Why Use This Command?

1. Creates one app target for iOS, macOS, tvOS, and visionOS, with a generated iOS launch screen, so one workspace serves every Apple platform.
2. Starts each platform with its own sample interface built on a shared feature, so you can see how a screen should feel on each device before writing your own.
3. Includes a Swift Testing target so the generated app starts with a working verification path.
4. Lints and type-checks the generated Node.js lifecycle helper while keeping native tests owned by Xcode.
5. Keeps Xcode build data inside the workspace so local and automated builds do not depend on a global DerivedData location.
6. Seeds editable App Store Connect metadata and asset directories under the repository's root `assets/` folder.
7. Includes an English Xcode String Catalog and uses SwiftUI's native localizable string types across every Apple destination.

## Requirements

- **macOS and Xcode** — Xcode supplies the Swift compiler, platform SDKs, and `xcodebuild`. Building for tvOS or visionOS also needs that platform's component installed in Xcode.
- **XcodeGen** — Install XcodeGen and make `xcodegen` available on your `PATH`.
- **Empty directory** or **<Terminology title="The top folder of the repo, where the root package.json lives" to="/docs/quickstart/terminology#git-and-workflow" color={true}>monorepo root</Terminology>** — Nova auto-detects whether to create a project or add a workspace.

## Platform Folders

Each platform folder holds only the screens that platform needs, while `Sources/Shared/` holds everything they have in common.
This keeps one platform's layout choices from leaking into another and lets you delete a platform without touching shared code.

### How the Folders Are Wired

- **Shared sources** — `project.yml` compiles `Sources/` for every platform but excludes the five platform folders.
- **Platform sources** — Each platform folder is added back with a `destinationFilters` entry, so Xcode compiles it only for its own destination.
- **Root view** — `Sources/App/App.swift` opens `iOS_RootView`, `MacOS_RootView`, `MacOS_12_RootView`, `tvOS_RootView`, or `VisionOS_RootView` for the platform being built.

Folder and type names follow Apple's platform spelling. Names that start with a lowercase prefix keep it (`iOS`, `tvOS`), and the rest start with a capital letter (`MacOS`, `VisionOS`).

### macOS and macOS 12

Both macOS folders compile for macOS. `MacOS` types are marked `@available(macOS 13.0, *)`, and `App.swift` checks `if #available(macOS 13.0, *)` to choose between `MacOS_RootView` and `MacOS_12_RootView`.

The generated macOS deployment target is newer than macOS 13, so `MacOS_12` stays dormant until you lower `options.deploymentTarget.macOS` in `project.yml` to `12.0`. The shared views already avoid newer APIs or check for them, so lowering the target needs no other change.

### Add or Remove a Platform

To remove a platform, it is recommended to change these places together:

1. Delete its folder under `Sources/`.
2. Remove the folder's `excludes` entry and its `path` entry from `project.yml`.
3. Remove the destination from `supportedDestinations` on the app and test targets.
4. Remove the matching branch from `rootView` in `Sources/App/App.swift`.

To add a platform, reverse the same steps: create the folder with a root view, add the `path` entry with `destinationFilters`, exclude the folder from the shared `Sources` entry, add the destination, and open the root view in `App.swift`.
Run `npm run dev` afterward so XcodeGen regenerates the Xcode project.

## Localization

Xcode discovers localizable SwiftUI literals during builds and keeps their source language in `Sources/Localizable.xcstrings`. Add languages and translations through Xcode's String Catalog editor; the same catalog serves every platform.

Nova types reusable launch-step and accessibility copy as `LocalizedStringKey` so moving a literal through a helper view does not silently make it untranslatable. No runtime localization dependency is required.

## Non-Interactive Mode

Agents and automation can create the root and first Apple app in one command, or omit `--name` to add the app from an existing monorepo root.

```bash
nova scaffold app apple --non-interactive --name my-apple-app --workspace-name client --bundle-id io.example.client --output ./my-apple-app
nova scaffold app apple --non-interactive --workspace-name client --bundle-id io.example.client --output ./apps/client
```

## Registration and Customization

Nova registers the workspace with the `app` role and `trackable` policy, then adds `swift`, `ios`, and `macos` to the root `project.platforms` list without removing existing entries. The generated package name follows `{projectSlug}-app-{workspaceName}`.

Nova does not guess one file artifact for the native workspace because Xcode emits different app, archive, and test products per Apple platform and signing choice. Add a named artifact after choosing the exact product that belongs in the root assembly.

The bundle identifier defaults to `com.example.{workspaceName}` when `--bundle-id` is omitted. Nova accepts ASCII letters, numbers, periods, and hyphens, preserves the supplied value exactly, and gives the unit-test target the matching `{bundleId}.tests` identifier.

The scaffold creates `en-US` metadata placeholders for iOS and macOS plus documented screenshot and creative-asset directories. Fill only the fields and asset targets you intend to change, then use [`nova integration app-store-connect`](/docs/cli/integrations/app-store-connect/metadata). Nova does not add `/assets/` to the generated `.gitignore`; store assets remain project-owned and trackable by default.
